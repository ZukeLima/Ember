Engineering standards

Breaking changes

Treat dataset/metric changes as breaking changes requiring documentation.

CI pipeline (proposed)

1

Install pinned Python/dbt dependencies.

2

Generate a tiny fixed-seed fixture.

3

Run Python unit tests and ingestion into an isolated DuckDB file.

4

Run dbt parse/build/test on fixture data.

5

Run reconciliation assertions and validate run artifacts.

6

Fail on critical violations; upload sanitized diagnostic artifacts if appropriate.

No secrets should be needed for the MVP. Generated datasets, DuckDB files, cache directories and potential personal data must be excluded from Git.

Security / data handling

  • Use synthetic customers with no real email/phone/CPF/CNPJ.
  • Do not copy proprietary employer data, analytics exports or brand assets into this public repository.
  • Store no authentication tokens in code.
