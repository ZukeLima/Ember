01 · Principles

What every screen should feel like

Truth over polish

A pretty dashboard without validated models is not done. Never show unvalidated numbers as facts.

Dense, not cramped

Show more numbers per screen, held together by an 8 px rhythm and quiet borders.

Say the status

Every state pairs a label and an icon shape with its tint: healthy, stale, invalid.

One definition

Tooltips quote the metric dictionary. The UI never redefines a formula.

Critical quality failure

Do

  • Use solids for fills, icons and the chart line.
  • Use the ink color for any status text.
  • Give inputs a #BFA896 edge so they stay visible.

Don't

  • Set text in warning (3.64:1) or white on it.
  • Put success text on bg (4.49:1).
  • Rely on border (1.15:1) as an input's only edge.

06 · Actions & focus

Few buttons, always obvious when focused

A dashboard reads more than it acts: one primary action per view at most. Proposed, not in v0.1.

VariantDefaultHoverFocusDisabled Primary Secondary Link Docs → Docs → Docs → Docs →

Focus ring: 2 px primary outline, 2 px offset, on every interactive element. Never remove it without a replacement.

07 · Data visualization

Charts that answer one question each

Series order (proposed)

1 · Net sales, the main series
2 · Comparison series
Previous period, reference only
Gridlines and empty bars

Blue and orange differ in lightness too, so they read in grayscale and for red/green color blindness. Status colors never encode series.

Rules

  • Y axis starts at zero for money; label the unit (R$) once, on the axis.
  • Tooltip shows date, value with 2 decimals and the timezone.
  • At most 2 series per chart; split instead of stacking more.
  • Highlight one point at most; everything else stays quiet.
  • Every chart ships with “View as table”.

08 · Layout

  • Content max width 1560 px inside a rounded panel, 28 px side padding, 64 px brand rail on the left.
  • KPI strip: 5 cards in a row at 1280 px, wrapping to 2 then 1.
  • Chart full width; breakdown table below it, scrolling inside its box.

09 · Icons

16 px, 1.5 px stroke, round caps, drawn in currentColor. Each status has its own shape, so it survives without color. Icon-only buttons carry an aria-label.

11 · Accessibility

  • Keyboard-operable inputs, explicit labels, meaningful focus.
  • Every chart has a tabular equivalent.
  • No reliance on red/green alone.
  • Text at 4.5:1 minimum; targets at 44 px.
  • Locale-aware BRL formatting and an explicit timezone label.

12 · UX acceptance

  • Filtering updates every metric and chart from the same curated snapshot.
  • KPI tooltips match the metric dictionary exactly.
  • Empty results show explanatory states, not zeros disguised as sales.
  • Warnings specify whether the data is stale or invalid.
  • Usable at 1280 px; narrow widths stack cards with no page overflow.
